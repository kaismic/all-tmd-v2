# ALL-TMD v2: controlled Sydney transfer study

This repository implements the report's controlled comparison: NOR-TMD only,
Sydney only, and pooled NOR-TMD + Sydney. Every condition uses one frozen,
participant-independent Sydney evaluation protocol. Sydney-containing conditions
use nested 10%, 25%, 50%, 75%, and 100% whole-session calibration subsets.

This is a cross-regional calibration curve: XGBoost is retrained on each pooled
training set, rather than pretrained and fine-tuned in the neural-network sense.
The repository retains `all-tmd-v1` history. It deliberately does not edit
`reports/report-6-revised.tex`; `report` produces inputs after real runs exist.

## Reproducibility contracts

- `manifests/sydney-166.json` freezes 166 pseudonymous sessions with session-ID
  digest `8931f5b287838320e9173639d4023da19f34271b6b8abdfdc63691102674124c`.
- Tram is outside the task, leaving 157 three-class sessions. The two sessions
  longer than two hours remain included because every upload was manually
  inspected. The 30-second minimum and sensor/window-quality checks still apply.
- `study-plan.json` defines the 33 parent configurations and analysis seed.
- `manifests/sydney-lopo.json`, generated after features, freezes seven LOPO
  folds. An existing different manifest is rejected.
- `model-lock.json`, generated by `promote-model`, freezes Sydney-free NOR-TMD
  model selection. Evaluation rejects feature, input, dependency, or lock-digest
  mismatches.
- `requirements.lock` pins the local and EC2 runtime.

Ingestion and feature caching are separate. Ingestion is keyed by the snapshot
and ingestion contract. Features are keyed by the ingestion artifact bytes,
feature contract, and quality settings. Deterministic entries use temporary
directories, atomic promotion, `_SUCCESS`, and JSON manifests. Training is never
cached: every result directory is named with its MLflow run ID.

## Data layout

Copy `.env.example` to `.env`, then set `ALL_TMD_DATA_DIR` to the host directory
containing the datasets (the local Windows example uses `D:/tmd-data`). If it is
unset, Compose falls back to `./data`. The selected directory must contain:

```text
data/
|-- nor-tmd-data/          # immutable NOR-TMD CSV input
`-- downloaded_sessions/  # Sydney .json or .json.gz payloads
```

Local verification fails on a missing eligible frozen session and ignores later
uploads. AWS queries the complete collector index and downloads only manifest IDs.

## Local Docker workflow

The wrappers build the pinned image, start a healthy MLflow server, record the
current commit, and invoke the CLI. On PowerShell:

```powershell
.\scripts\study.ps1 snapshot verify --input-dir /data/downloaded_sessions
.\scripts\study.ps1 prepare-data
.\scripts\study.ps1 create-lopo
.\scripts\study.ps1 tune-source --output-root /data/all-tmd-v2-results
.\scripts\study.ps1 promote-model --run-id <tuning-run-id> --output-root /data/all-tmd-v2-results
.\scripts\study.ps1 run-study --output-root /data/all-tmd-v2-results
.\scripts\study.ps1 report --results-root /data/all-tmd-v2-results --output-dir /data/report-artifacts
```

Use `bash scripts/study.sh ...` with the same arguments on Linux/macOS. MLflow is
at <http://localhost:5002>. Tuning is fixed at 45 XGBoost Optuna trials, five
participant-grouped NOR-TMD folds, pooled out-of-fold macro F1, and seed 42.

Each study parent has seven nested held-out-participant runs. Parent artifacts
hold pooled predictions and metrics. Child artifacts hold fold predictions,
metrics, train/test fingerprints, effective calibration proportions, and native
MLflow dataset inputs.

## AWS EC2 workflow

The CloudFormation and Systems Manager workflow is namespaced under
`all-tmd-v2`. After deploying and uploading the immutable NOR-TMD input:

```powershell
.\scripts\aws\prepare-run.ps1 -Mode Tune
.\scripts\aws\start-run.ps1 -RunId <run-id>

.\scripts\aws\prepare-run.ps1 -Mode Full
.\scripts\aws\start-run.ps1 -RunId <run-id>
.\scripts\aws\download-results.ps1 -RunId <run-id> `
  -Destination .\aws-results\<run-id>
```

Full/smoke bundles require `model-lock.json` and
`manifests/sydney-lopo.json`, checksum every contract, and identify an exact
reachable commit. Each sweep owns its SQLite backend, artifact directory,
results, logs, and resource report; it never uses a worker-wide MLflow database.

## Import isolated AWS runs

Do not merge SQLite files. Import a downloaded store into canonical local MLflow:

```powershell
.\scripts\study.ps1 import-mlflow `
  --source-database /data/aws-results/<sweep-id>/mlflow/mlflow.db `
  --destination-uri http://mlflow:5002 `
  --sweep-id <sweep-id>
```

The importer recreates parameters, complete metric histories, timestamps, tags,
dataset inputs, artifacts, statuses, and nesting using MLflow client APIs. It
preserves original IDs and sweep IDs, remaps parents, and is idempotent for each
`(sweep ID, original run ID)` pair.

## Report outputs

After all 33 parents exist, `report` validates the grid/shared evaluation digest
and writes:

- `transfer-curve.csv`, `.png`, and `.pdf` for macro F1/balanced accuracy;
- `per-class-performance.png` for recall/F1;
- `controlled-comparison.tex` at 100% calibration;
- `paired-differences.csv` and `.tex`, including 95% intervals; and
- `study-summary.json` with validation and data/model/split digests.

Intervals use 5,000 paired hierarchical bootstrap iterations with seed
`20260903`, resampling seeds, participants, and sessions identically across a
comparison and redrawing samples without every configured class.

## Verification

```powershell
python -m pytest -q
docker compose config
sam validate --template-file aws/cloudformation.yaml --lint
```

Tests cover cache boundaries/recovery, snapshot invariants, LOPO leakage and
pairing, nested subsets, model locks, isolated outputs, synthetic reporting, AWS
bundles, and idempotent MLflow import when MLflow is installed.
